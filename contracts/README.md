# 影序共享协议 v1（并行开发基线）

2026-10-25：用户确认桌面 V2 前端，授权本地后端与 Agent/云端两个会话并行开发。

这里是供两边开发的接口约定，不代表服务已经部署或桌面已经联调。

- `sync-event-v1.schema.json`：任务摘要事件。对应本地 SQLite outbox 的投影；不是原始 jobs/job_items 表结构。
- `agent-proposal-v1.schema.json`：Agent 提议。只用于表达意图，不构成文件操作授权。
- 数据库 owner、设备归属、调用端类型和权限必须由服务端根据已验证会话取得；不能信任客户端自填字段。
- 本地数据库行与协议字段需显式映射。不得直接上传 Rust `Job`：其中包含本地指纹、路径、文件级细节。
- `source`、`paths` 只在用户允许路径同步时存在；关闭后省略字段并删除既有云端路径字段。原片、GPS/EXIF 原文、令牌禁止出现在事件里。
- 数字按 JSON 安全整数传输；超出范围需新协议，不静默截断。

## 同步语义

桌面先提交本地任务与 outbox，再异步上传。云端以登录用户隔离，验证设备归属；`eventId` 和 `(owner,deviceId,sequence)` 双重幂等，相同键不同正文返回冲突，不能覆盖。每批确认实际持久化的 ID；桌面只确认这些事件，重试不改变已成功文件结果。

快照是权威状态；WS 是增量提示。重连先拉快照，再按游标补齐；缺口重拉。离线展示最后同步时间。删除同步记录/注销须产生删除语义，迟到旧事件不得恢复已删除记录。

首版 schema 只涵盖 `job.snapshot.v1`。Agent 会话、设备、预设、缩略图、删除事件需由云端会话添加独立 schema 并记录版本，不能把它们塞进该事件的任意扩展字段。

## Agent 边界

云端提议只携带文件 ID 和不透明目的地授权 ID；本地路径由桌面自己的授权表解析。桌面核对有效期、当前登录设备、来源指纹、目的地和权限，生成本地不可变预览，用户本地确认后执行并记录结果。

`origin` 必须由认证后的服务端会话绑定，不能仅根据请求 JSON 决定。手机 Agent 只能查云端同步资料、操作手机自己的备份；拒绝手机触发桌面文件写入和桌面任务控制。此规则适用于 REST、WS、队列与重放事件。

来源移除不作为云端 Agent 通用工具开放：转移任务完成校验后，由桌面独立生成短时一次性移除计划并进行第二次确认。

## 修改方式

现有两个 v1 schema 由本地后端会话维护；云端会话可新增自己的 OpenAPI 和其他 schema。需要改变 v1 字段时，在 `docs/协作交接/协议变更请求.md` 追加兼容性说明，双方确认再更新版本。不要直接修改对方工作目录或删除已有字段。
