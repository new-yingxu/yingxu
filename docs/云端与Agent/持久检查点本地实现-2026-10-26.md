# LangGraph 持久检查点：本地实现交接

仅完成本地实现与 SQLite 验证，未连接 CloudBase，未部署。

新增 `app.graph_checkpoints.PrincipalCheckpointSaver`：构造参数 `store_factory`（返回全新 Store 的 context manager）、`owner_id/device_id/origin/session_id/thread_id`。`thread_id` 由服务端决定，不能使用客户端任意值。导入模块后再执行 `Base.metadata.create_all()`，两个 ORM 表才会被注册。

每次操作独立创建并关闭 Store；SQL 与 REST RPC 均先锁 owner，再检查设备注册/撤销、origin、会话删除墓碑和 `sync_agent_sessions`。关闭偏好后读取为空、后续写入跳过，允许已计费的模型调用正常返回；撤销设备和删除会话仍拒绝。开启偏好不会删除旧历史，产品层不要自动重新运行已完成/失败的付费调用。恢复模型必须复用现有 request reservation，不能以检查点存在作为重新计费授权。

实现同步 `get_tuple/list/put/put_writes/delete_thread`，持久化 parent checkpoint、typed blob 和 pending writes，按 task_path/task_id/index 排序。负索引写覆盖，普通索引首次写入保留。JsonPlusSerializer 禁用 pickle fallback，typed blob 限制 2 MiB；配置和 Store 凭据不进入持久化载荷，敏感键拒绝进入状态。

v11 SQL 依赖 v10，新增两个带 RLS 的表、service_role 专属 RPC，并替换会话删除函数以同时清除检查点。应用端还需更新 SQLStore.delete_session 对应清除；本代理未改既有文件。RPC 不接受动态表名/列名，顶层和 pending-write payload 拒绝未知键。迁移需要主代理在隔离 PostgreSQL 中执行、重复执行并验证授权。

验证命令：`cd cloud-service && /tmp/yingxu-cloud-py311/bin/python -m unittest discover -s tests -p test_graph_checkpoints.py -v`。2026-10-26：5 tests / 0.148s / OK。包含真实 compiled LangGraph interrupt 后创建新 saver 恢复、并行节点失败后的 pending writes 恢复（成功节点不重复执行）、owner/thread 隔离、关闭偏好/删除/撤销、mid-run opt-out、负索引写入以及凭据拒绝。

当前未实现异步 saver API；应用应使用同步 graph.invoke。PostgreSQL/RPC 行为以主代理后续隔离本地验证为准，不能据此宣称云端已验证。

## 同轮后续接线

已在 `main.py` 的本地 `create_all` 前注册模型；`SQLStore.delete_session` 在 owner 锁、设备校验和墓碑创建的同一事务中清除两张检查点表，使用 local import 避免循环依赖。`build_turn_graph` 接受可选 `checkpointer`；`run_turn_graph` 接受 `checkpointer/thread_id/resume`，默认调用不变。`resume=True` 恢复失败后 pending tasks，`resume=Command(resume=...)` 恢复中断；带 checkpointer 时必须明确给出服务端 thread_id。HTTP turn 尚未接入持久 saver，无自动重放。

新增真实 wrapper 中断恢复、失败恢复、SQLStore 删除清理和其他 owner 不受影响验证：checkpoint suite 7 tests / 0.196s / OK，既有 agent_graph suite 3 tests / 0.005s / OK。全量本地 `python -m unittest discover -s tests -q`：77 tests / 0.835s / OK (skipped=41)。跳过的测试未作为已验证证据。


## 0.5 候选数据库要求

应用 readiness 与打包清单统一使用 config.REQUIRED_SCHEMA_VERSION=11，缺少 v11 时生产 readiness 拒绝就绪。v11 仅本地准备、未应用云端；云端仍 schema10。关闭 sync_agent_sessions 在 owner 事务锁内清除两张检查点表，重新开启不恢复旧检查点；既有历史轮次仍遵循既有历史策略。SQL 与 service_role RPC 的关闭/重开行为均纳入本地真实 PostgreSQL 测试。部署前必须重新构建，旧0.4.1包不可当作当前源码包。


## 0.5.0 持久检查点与 HTTP 显式恢复（仅本地）

POST `/v1/agent/turns` 新增 `resume` 布尔字段，默认 false。显式恢复需保持 sessionId、turnId、query、useModel 一致；thread ID 由服务端绑定身份后派生，客户端不可指定。仅稳定 session/turn 且开启会话同步才保存检查点。完成态仍检查业务 ledger；pending/uncertain 不得自动重新调用供应商。缺检查点 409 CHECKPOINT_NOT_FOUND，关闭同步 409 CHECKPOINT_SYNC_DISABLED，缺稳定标识 422 RESUME_REQUIRES_SESSION_AND_TURN；删除会话 410、撤销设备 403。每个图节点独立 Store，释放请求读事务，单连接池测试无死锁且归还连接。

Python3.11/PostgreSQL17.11 隔离实例：85 tests，74 passed，11 skipped；v11 重复迁移和 anon/authenticated 表/RPC拒绝检查通过。检查点关闭同步同事务清理，重新开启不复活。证据：checkpoint-http-postgresql-regression-20261026.log。HTTP 恢复 API 六项采用本地 SQLite，真实 PG saver/RPC另测，不声称真实云HTTP恢复通过。
