## 一、给 AI 的三条总指令

1. **一句话主题**：影序是一款本地优先的智能影像备份与整理桌面应用，主张「把影像的备份与秩序，留在你自己的硬盘上」。
2. **视觉基调**：米白纸感 + 深松绿 + 极少量暖金，留白充足、线条克制，像专业工作室的台账工具；不要科技蓝、渐变、发光、赛博朋克。
3. **叙事纪律**：每页只讲一个结论；已验收 / 本地候选 / 待接入三种状态必须区分，不得混写。

## 二、定位（三句话讲清）

**原文使用 · 主标题**
> 把影像的备份与秩序，留在你自己的硬盘上。

**原文使用 · 副标题**
> 影序负责扫描、复制、校验、整理和检索。原片始终只读，副本逐文件比对 SHA-256；断网、离线、换盘都能用，不需要把照片交给任何云端。

**原文使用 · 品牌短句**
> 本地影像备份与整理 · 原片只读 · 副本可校验

| 维度 | 事实 |
|---|---|
| 用户 | 摄影师、影像工作者、需要长期管理大量照片视频的个人 |
| 平台 | Windows / macOS 桌面端为主；Android / iOS 为只读伴侣；官网为下载与说明 |
| 战场 | 相机卡与移动硬盘的导入、多副本备份、完整性校验、命名与检索、交付 |
| 立场 | 原片不上传影序自有云端；备份完全离线可跑；Agent 只提议，写操作本地二次确认 |
| 差异 | 逐文件 SHA-256、多目的地独立成败、任务可恢复、失败保源、AI 只调用白名单工具 |

## 四、功能框架

### 4.1 四条主线（桌面端）

| 主线 | 用户动作 | 产品必须保证 |
|---|---|---|
| 复制新内容 | 插卡 → 扫描预检 → 选目的地 → 预览命名 → 确认执行 | 不自动写入；不覆盖同名文件；每目标独立结果 |
| 转移老内容 | 选来源/目标 → 筛选 → 分析废片与重复 → 确认 → 转移 | 只有目标副本校验通过且来源未变化，才可移除来源 |
| 归档记录 | 筛选搜索 → 看详情 → 读报告 → 定位文件 | 成功/部分完成/失败/取消/暂停五态可区分 |
| Agent 助手 | 自然语言查找、问状态、预览整理 | 查找可直接做；改名/移动/上传/清理必须先确认 |

### 4.2 桌面端 12 个功能页（PPT 直接引用）

工作台 · 复制新内容 · 转移老内容 · 影像资料库 · 归档记录 · 任务详情 · Agent 助手 · 账号与设备 · 导入预设 · 恢复与健康审计 · 交付包 · 偏好设置

### 4.3 增值能力（可作为"完整度"论据）

- **恢复与健康审计**：对已登记副本回读校验，定位损坏副本，从健康副本恢复到新位置。
- **导入预设**：命名规则、目的地组合、筛选策略可保存复用，执行前仍展示预览。
- **客户交付包**：选中素材副本 + 联系表 + 清单与 SHA256SUMS，写入独立目录，原片不动。
- **质量筛选**：过曝、失焦、重影、损坏/不可解码只输出「待复核」候选与理由、置信度。
- **托盘常驻**：关窗后台继续，菜单栏/托盘恢复窗口，退出前可恢复收尾。

### 4.4 移动端与云端的边界（务必按此表述）

- 手机是**只读伴侣**：看桌面任务进度、速度、阶段、逐目的地结果、最后同步时间。
- 手机**不能**启动/暂停/取消桌面任务，不能打开电脑文件，不能用路径控制电脑。
- 手机可备份自己的照片视频，可让 Agent 查本账号已同步数据、管手机自己的备份。
- 云端只做账号、设备、任务摘要、Agent 会话、可选缩略图（最长边约 512px）与可关闭的路径/电脑名；**原片、令牌、精确 GPS/EXIF 不上云**。

## 五、技术框架（供架构页使用）

### 5.1 五层结构

```text
桌面 UI      Vue 3 + TypeScript + Vite（12 页，深浅主题）
桌面宿主     Tauri 2 / Rust：窗口、权限、托盘、IPC、生命周期
本地核心     Rust 有界 worker + SQLite/FTS5：扫描、复制、SHA-256、任务队列、
             报告、健康审计、恢复、交付包、照片/RAW/视频分析
云端         FastAPI + WebSocket（CloudBase 托管）+ PostgreSQL
Agent        LangGraph 状态图 + 白名单工具；只读工具 + 受控提议
外部         百度网盘官方 OAuth/上传；本地/云端模型（BYOK）
```

调用边界一句话：**UI 调本机只走 Tauri IPC，UI 调云端只走 HTTPS/WSS，云端永不直接访问本机文件系统。**

### 5.2 技术栈与理由

| 层 | 选型 | 理由（可直接上屏） |
|---|---|---|
| 界面 | Vue 3 + TS + Vite | 组件化、构建快，深浅主题切换成本低 |
| 宿主 | Tauri 2 / Rust | 安装包小、原生文件权限可控、托盘与单实例成熟 |
| 本地核心 | Rust + SQLite/FTS5 | 大文件流式哈希、崩溃可恢复、检索不依赖云 |
| 影像 | 自解析 TIFF/RAF/EXIF、MP4/MOV、ffmpeg 关键帧 | 少依赖、可控内存上限、原片只读 |
| 云端 | FastAPI + PostgreSQL（CloudBase HTTP 函数） | 无状态横向扩展、迁移可控、按量成本低 |
| Agent | LangGraph StateGraph + 类型化工具白名单 | 有限流程、可审计、模型不握执行权 |
| 协议 | contracts v1 JSON Schema | 双端并行开发共用基线，改字段需提变更请求 |

### 5.3 数据流（一页图建议）

```text
相机卡（只读） → 预检计划 → 用户确认 → 临时副本 → SHA-256 校验 → 原子提交 → 目标副本
                                              ↓
                                 SQLite 任务/目标/文件/审计 → 报告 → 交付包
                                              ↓
                                    outbox 事件 → 云端快照 → 手机只读
```

### 5.4 安全设计（最能体现专业度的一页）

1. 来源默认只读，新增文件只写用户选定目标。
2. 预检路径、权限、空间、符号链接、来源/目标嵌套后才执行。
3. 独占临时副本 + 流式 SHA-256 + 原子提交，禁止覆盖。
4. 同名同哈希跳过；同名异内容加序号，不覆盖。
5. 转移需二次确认，来源仅移入可撤回目录；失败/拔盘/取消一律保源。
6. 每个目的地独立排队与重试，一家失败不改写另一家结果。
7. 任务状态落 SQLite 检查点，重开应用可恢复，未验证成功不得显示成功。
8. Agent 不扩权、不执行任意 Shell、不隐藏副作用；写操作留审计。

**三种"像"必须分开讲**：SHA-256 = 字节完整性/精确重复；感知相似 = 连拍与视觉接近；质量信号 = 拍摄缺陷候选。三者不可互相替代。

### 5.5 协议与同步

- 事件幂等：`eventId` + `(owner, deviceId, sequence)` 双重幂等；同键不同正文判冲突，不覆盖。
- 恢复顺序：先取权威快照，再按游标补增量；缺口重拉；离线标注最后同步时间。
- 令牌与密钥：系统钥匙串/凭据库或服务端 Secret，不进前端、日志、仓库、聊天。

## 六、开发框架（"怎么造出来的"）

### 6.1 分工模型（可作为"工程能力"页）

| 角色 | 负责范围 |
|---|---|
| 产品/用户 | 确认框架、页面走查、授权第三方资质 |
| 桌面核心线 | Rust 本地核心、媒体分析、网盘接入、打包发行、官网 |
| 前端线 | 12 页界面、适配层、云客户端、Agent UI |
| 云端/Agent 线 | FastAPI、身份边界、LangGraph、数据库 schema |
| 移动端 | Expo（Android/iOS），独立工程 |
| 独立验收线 | 产物哈希、来源复核、Windows 实机、隐私检查 |

### 6.2 协作纪律（可提炼为三句）

- **目录独占**：每人只写自己目录，跨目录改动需交接文档。
- **证据驱动**：每个结论配日志/哈希/回执，不以"编译通过"替代"运行验收"。
- **闸门先行**：缺 API 资质、密钥、账号授权时停在依赖点，不造假成功。

### 6.3 质量门禁（实际存在的命令级门禁）

`cargo test`（59 项）· `cargo clippy -D warnings`（0 警告）· `cargo fmt --check` · 前端 `vite build` · 云端 `unittest`（93 项）· 版本号一致性校验脚本 · 发布产物 SHA-256 与 ZIP 逐文件回读。

| 次要文字 | `#6F706A` |
| 分隔线 | `#E9E6E0` |

### 7.2 字体与版式

- 字体：`PingFang SC` / `Noto Sans SC`，回退系统无衬线；不用衬线体、手写体。
- 16:9，页边距 ≥ 0.8 in；标题 36–48pt，正文 18–22pt，注释 12–14pt。
- 单页信息块 ≤ 3；每页顶部一句结论，正文只放支撑证据。
- 圆角：卡片 10–14px，按钮 8–10px，标签全圆角；阴影极轻，靠留白与分割线分层。
- 图标：线性描边，不填充；状态必须"颜色 + 文字/图标"双编码。

### 7.3 品牌图形语言

现有标志为**深绿圆角方块内嵌 2×2 米白圆点，整体逆时针倾斜约 4°**。四点 = 多副本/多目的地，也可读作影像网格。

可延展为：封面视觉锚点、页脚纹理、章节分隔符、要点符号；保留 4° 倾斜作为品牌辨识点。**不要**使用任何临时占位图标（例如绿色方块 AI 字母图）。

### 7.4 视觉禁令

渐变、发光、玻璃拟态、3D 立体字、拟真相机与云盘贴图、多色 emoji、彩色大面积背景、超过三层的架构图、满屏小字。

## 九、可上屏文案卡（原文使用）

**卡 A · 四件事**

| 词 | 说明 |
|---|---|
| 备份 | 按来源目录生成计划，逐文件复制到 1–8 个本地目的地。先预览再执行，任务可暂停、可恢复，绝不覆盖已有文件。 |
| 校验 | 复制过程与完成后都做 SHA-256 比对，副本清单可随时复查。校验失败的条目单独列出，不会写成「成功」。 |
| 整理 | 用 EXIF 拍摄时间、机型与事件规则命名，支持 RAW 内嵌预览与视频元数据。质量信号只输出「待复核」，不自动删片。 |
| Agent | 把重复操作交给对话式助理：生成计划、解释失败原因、汇总报告。所有危险动作都要你确认后才执行。 |

**卡 B · 差异化**

> 和网盘不是同一件事。原片不先上传；副本逐文件校验；断网也能用；删除要二次确认且可撤销；大文件走本地直读，不受上行带宽限制。

**卡 C · 三端定位**

| 端 | 一句话 |
|---|---|
| 桌面端 | 扫描、复制、校验、整理、检索、交付的主战场（12 个功能页）。 |
| 移动端 | 只读伴侣：看桌面任务进度，备份手机自己的素材。 |
| 官网 | 介绍、下载、版本说明与隐私政策，7 个静态页。 |

**卡 D · 当前状态**

> 已经能用：本地备份与校验、任务队列与恢复、报告与交付包、照片质量信号与缩略图、RAW 内嵌预览、MP4/MOV 元数据与抽帧、百度网盘上传。
> 还没做：正式代码签名、应用内自动更新、夸克网盘接入、移动端实现、正式云身份登录。

## 十一、红线（内容与画面）

**内容禁止**
1. 不得写"云端备份""照片上传到服务器""同步到云"。
2. 不得写"自动修复过曝/模糊""自动删除废片"——只输出「待复核」。
3. 不得写"支持所有 RAW 格式"——用「支持主流相机 RAW 预览」，并限定"已验证样本范围"。
4. 不得写"已正式签名""已上架应用商店""已公测上线"。
5. 不得让手机端表现为能控制桌面任务或打开电脑文件。
6. 不得出现价格、免费承诺、下载量、用户数、融资、团队规模等未经验证的信息。
7. 不得把 Mock 演示数据、本地候选版本描述为线上已实现功能；线上云端仅为 0.2.0 预发布。

**画面禁止**
1. 不使用他人拍摄的照片；需要实拍质感时用抽象色块、纯排版或界面截图代替。
2. 不使用临时占位图标（绿底 "Ai" 字母方块）。
3. 不用红色表达"普通"或"强调"，红色只表示失败/警示。
4. 不在架构图里堆超过三层的框与交叉箭头。
5. 不把状态只靠颜色区分，必须配文字标签。
