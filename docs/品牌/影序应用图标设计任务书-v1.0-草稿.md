# 影序 YINGXU 应用图标设计任务书 v1.0（草稿）

> **交付对象：** 受托设计影序应用图标的设计同学
> **文档状态：** 草稿，供设计提案与评审；项目负责人确认前，不替换应用现有图标、不接入发布包。
> **适用范围：** Android Expo、iOS PWA、Windows/macOS 桌面端及下载网页。iOS 当前采用 PWA。

## 1. 任务目标

为影序设计一套跨端一致的应用图标，让摄影师一眼感受到“影像被有序、安全地保存和管理”。图标应简洁、专业、温和，在手机桌面、浏览器主屏幕、macOS Dock、Windows 任务栏等小尺寸位置仍清晰可认。

影序是摄影领域的智能影像资料管理软件，覆盖本地备份、校验、分类、检索、质量筛选和用户自行选择的网盘上传。图标表达产品整体，不要只代表相机、云盘或某一项功能。

## 2. 品牌基线

| 项目 | 约定 |
|---|---|
| 品牌名 | 影序 YINGXU |
| 主色 | 深森林绿 `#273D31` |
| 深色 | `#253A2F` |
| 浅底色 | 暖米白 `#F4F2ED` |
| 选中绿 | `#27804A` |
| 进度点缀 | 暖金 `#DDBA76`，少量使用 |
| 视觉气质 | 安静、可信、专业、温和，有摄影感；避免像安全软件或通用云盘 |

桌面与移动端沿用同一套视觉基线。上述颜色来自现有产品界面；设计同学可以微调图标内部色彩，但请说明理由并保持整体协调。

## 3. 创意方向与提案要求

### 推荐方向：叠影归序

从“照片/影像画面”和“有序归档、多份备份”中提炼一个原创的抽象符号。可以探索取景框、画面窗口、错位叠层、序列节奏或负空间等表达方式；最终只保留一个有记忆点的主图形，不要把功能清单画成图标拼贴。

设计时请优先回答：

1. 这个轮廓能否在 32 px 下仍被认出来？
2. 是否同时让人联想到影像与整理/保存？
3. 是否看起来属于温和、可信的摄影工作流产品？
4. 是否避免让用户误以为原片默认上传到影序自有云端？

### 首轮提案

- 先交 2 个黑白剪影方案，保持同一创意方向，重点比较轮廓和负空间。
- 每个方案附 1 句含义说明；不要先花时间做复杂渲染或完整品牌手册。
- 选出轮廓后，再提交 2 个配色稿：优先使用深森林绿与暖米白；暖金只作小面积强调。
- 项目负责人确认方向后，再完成精修和平台预览。

## 4. 造型规范

- 画布为正方形；核心符号居中，并为系统裁切和不同图标遮罩留足安全区。
- 主体尽量由 1–3 个大形状组成，确保小尺寸轮廓清楚、对比充分。
- 图标本体不写“影序”“YINGXU”“AI”或“备份”等文字；应用名称由系统显示在图标下方。
- 不在母版预画 iOS 圆角方形遮罩；各平台按自身规则裁切或加遮罩。
- Android 需考虑圆形、圆角方形、方形及单色主题图标的可读性。
- 同一主符号跨端保持一致；只允许因安全区、遮罩或平台资源格式作必要适配。

## 5. 避免事项

- 不使用通用相机机身加镜头的模板，不直接拼贴相机、文件夹、硬盘、网盘、盾牌、锁、齿轮、AI 星光等现成符号。
- 不把云朵作为主要视觉，避免暗示影序会替用户托管原片。
- 避免细线、微小光圈叶片、复杂纹理、拟真照片、重阴影、金属质感、强发光和复杂渐变。
- 不复制 Apple、Google、摄影品牌或竞品图标；不使用来源不明或授权不清的素材、字体。
- 当前仓库里的 `影序图标-源图-512.png` 和应用图标仅是现有视觉参考，**不代表已获项目负责人确认**。样稿中的细节（包括字母或色彩）不要求沿用；请以本任务书和已确认品牌色为准重新提案。

## 6. 交付文件

### 必交源文件

- 可编辑 Figma、SVG 或 AI 源文件，图层命名清楚，主图形和背景可分别编辑。
- 说明颜色 HEX、构图/安全区、导出方式；若使用外部资源，列明来源和授权。
- 交付一张提案预览图，含黑白方案、配色方案和小尺寸测试。

### 最终方向确认后再导出

| 用途 | 交付内容 |
|---|---|
| 通用母版 | 方形 1024×1024 PNG（sRGB）；另交可编辑矢量源文件。背景与主体是否透明需在源文件中分层保留 |
| iOS PWA | 180×180 `apple-touch-icon`；Web Manifest 192×192、512×512；512 px maskable 版本并检查安全区 |
| Android Expo | 普通图标、adaptive icon 前景/背景、单色 monochrome 图层；遵循 Expo 当前配置要求 |
| Windows/macOS | 高分辨率母版；供开发端生成 ICO/ICNS 的清晰素材，并提供小尺寸预览 |
| 下载网页 | 32×32 favicon 及网页触摸图标，沿用同一视觉，不另做一套 |

像素尺寸和具体资源字段由开发同学接入时按当前 Expo、PWA 与 Tauri 配置复核。设计同学不需要修改业务代码、打包配置或发布文件。

## 7. 评审与验收

请在一页预览中展示：

1. 两个黑白剪影方案及简短含义说明。
2. 选定方向的配色稿。
3. 1024、180、64、32 px 的缩放效果与灰度效果。
4. Android 圆形/圆角方形/方形遮罩和单色图标预览。
5. iOS PWA 主屏幕、macOS Dock、Windows 任务栏/开始菜单的小尺寸效果。

验收条件：

- 不依赖文字说明，主图形在 32 px 下仍可辨识，缩放时没有粘连或关键细节消失。
- 同时传达影像与有序管理/保存，不造成“影序云端保存原片”的误解。
- 不同平台保持同一主符号；遮罩后主体不被切边，浅/深背景上都清楚。
- 提案包括可编辑源文件和导出说明；项目负责人确认后才替换应用资源。

## 8. 交接流程

1. 设计同学提交首轮黑白提案，等待项目负责人选方向。
2. 设计同学提交配色稿与平台预览，等待项目负责人确认最终方案。
3. 确认后交付源文件和最终导出；开发同学再接入各端资源并检查实际运行效果。
4. 设计稿确认、资源导出、代码接入、安装包验证是不同步骤；完成设计稿不等于各端已经验收。
