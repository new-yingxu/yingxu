# 影序 YINGXU 应用图标设计任务书 v1.0（草稿）

> 交付对象：负责影序品牌图标的设计同学
> 状态：待产品确认的设计任务书；图标方案先出预览，负责人确认后再作为正式资产替换应用图标。
> 适用端：Android Expo App、iOS PWA 主屏幕图标、Windows/macOS 桌面应用、下载网页。iOS 当前采用 PWA，不制作未签名 IPA。

## 1. 设计目标

为影序设计一个跨设备一致、容易记住的应用图标。用户第一眼应能联想到“摄影影像”和“资料有序、安全备份”，同时保持简洁，在手机桌面小尺寸、浏览器主屏幕和桌面 Dock/任务栏中都清楚。

图标要表达影序的整体产品，而不是某一个功能：影像导入、整理、质量筛选、备份和检索。品牌名为“影序 YINGXU”。

## 2. 品牌基线

| 项目 | 设计依据 |
|---|---|
| 品牌主色 | 深森林绿 `#273D31` |
| 品牌深色 | `#253A2F` |
| 浅色背景 | 暖米白 `#F4F2ED` |
| 进度强调色 | 暖金 `#DDBA76`，只作少量点缀 |
| 成功色 | `#27804A` |
| 产品气质 | 安静、可信、专业、温和、摄影感；不要像硬件工具或企业云盘 |
| 当前素材情况 | 当前工作区未发现正式品牌标志源文件；颜色以移动端和桌面草稿中已经统一的语义色为准 |

## 3. 推荐创意方向：叠影归序

以一个简化的“影像窗口”为主体，用少量重叠的画框/图层表达照片与多份安全副本；内部负空间可融入简洁的光圈或取景窗结构，体现摄影。整体采用抽象几何图形，避免直接堆叠相机、云盘、硬盘、文件夹和 Agent 等多个小图标。

建议视觉结构：

- 深森林绿作为主背景，尽量使用纯色或极轻微的色阶变化。
- 中央主体使用暖白/米白的清晰几何轮廓；主体略有层叠关系，但小尺寸仍是一眼可识别的单一符号。
- 暖金可用于一个小型光点、层次边缘或关键负空间，不超过主体视觉面积的少量比例。
- 让“照片窗口/光圈”与“归档层叠”形成一个完整符号，不要把完整字母、中文或多个功能符号硬塞进去。

请先提交 **2 个黑白剪影草图**，确认轮廓后再做 **2 个配色小稿**。建议围绕同一创意做轻微差异，方便比较识别度；不要做成两套完全不同的品牌方向。

## 4. 造型与视觉要求

- 画布使用正方形；主体居中，在系统可能裁切/加圆角后仍保持完整。图稿不要预先画 iOS 圆角方形边框，平台会自行处理图标形状。
- 主体轮廓尽量由 1–3 个大形状构成；避免细线、微小文字、复杂渐变、照片缩略图、细碎光圈叶片和低对比纹理。
- 在 1024 px、180 px、64 px、32 px 以及单色/灰度预览下都要可辨。小尺寸下如果层叠细节消失，优先保留主轮廓，删除装饰细节。
- 图形需在浅色/深色桌面背景、各类 Android 图标遮罩（圆形、圆角方形、方形）和 iOS PWA 主屏幕上保持对比度和视觉中心。
- Android 需单独检查自适应图标前景安全区和单色主题图标；不把主体贴近边缘，不在前景层自带阴影或圆角遮罩。
- iOS PWA 提供方形 `apple-touch-icon` 与 Web Manifest 图标；无需为 PWA 制作 Icon Composer 原生分层包。若日后改为 iOS 原生 App，再按当时 Apple 图标规范另做暗色/透明/着色等变体。
- 不在图标中写“影序”“YINGXU”“AI”“备份”等文字；应用名称会显示在图标下方。

## 5. 请避免

- 常见的“相机机身 + 镜头”通用模板，或直接使用相机/文件夹/云盘的现成图标拼贴。
- 过度表现“云端”，以免让用户误解原片会上传到影序自有云端。产品的原片仍由用户选择本地磁盘/个人网盘保存。
- 锁、盾牌、勾号、齿轮、AI 星光等元素同时出现，造成安全软件/系统工具的感觉。
- 过多小光圈叶片、发丝细线、细小文字、拟真相片、复杂阴影、强发光、金属质感和重渐变。
- 复制 Apple/Google/竞品的现有图标或使用未经授权的素材。图形需为原创并提供可编辑源文件。

## 6. 交付资产

### 设计源文件

- Figma 源文件或 SVG/AI 矢量源文件，图层命名清晰，主图形、背景、层叠细节可单独编辑。
- 说明所用颜色 HEX、构图比例、主体安全区和导出方式；若用了字体/素材，注明名称与授权来源。推荐图标本体不使用文字和外部图片素材。

### 母版与平台导出

请提供完整方形、不带预制圆角的源图，并从同一母版派生平台文件：

| 用途 | 交付建议 |
|---|---|
| 通用母版 | 1024×1024 px、PNG（sRGB、不透明背景）；另交可编辑 SVG/设计源文件 |
| iOS PWA | 180×180 px `apple-touch-icon.png`；Web Manifest 图标 192×192 与 512×512 px；512 px 另提供 maskable 版本并检查安全区 |
| Android Expo App | 前景透明图层、背景色/背景图层、单色 monochrome 图层；另提供普通方形预览 PNG。具体 Expo 资源命名由开发同学接入 |
| Windows/macOS 桌面 | 交付高分辨率母版 PNG/SVG；由开发同学按打包配置生成 ICO/ICNS，设计同学提供圆角/小尺寸预览图即可 |
| 网页 | favicon 32×32 px 与网页触摸图标；从母版导出，不另起视觉方向 |

各平台的最终像素尺寸与资源字段由开发同学接入时按目标 Expo SDK、PWA manifest 和桌面打包配置复核；设计同学先保证矢量母版和分层资产完整。

## 7. 评审预览与验收标准

交付前请提供一页预览图，至少包括：

1. 两个黑白剪影并排比较。
2. 推荐配色方案的完整图标。
3. iPhone 主屏幕浅/深壁纸上的图标效果。
4. Android 圆形、圆角方形、方形遮罩及单色主题图标效果。
5. macOS Dock、Windows 任务栏/开始菜单的小尺寸效果。
6. 1024、180、64、32 px 缩放和灰度预览。

验收标准：

- 设计同学与未参与设计的人都能在小尺寸下辨认出同一个标志；不依赖文字说明理解主体。
- 视觉上同时有摄影影像感与“有序保存/层叠副本”的暗示，不误导为云存储或单一相机品牌。
- 所有平台使用同一个主符号和色彩关系；不同平台只调整裁切、图层和资源格式。
- 图标在不同遮罩与浅/深背景下没有主体被切掉、线条粘连、颜色融入背景或核心含义消失。
- 交付包含源文件、母版、各平台导出和上述预览；项目负责人确认后才替换应用现有图标。

## 8. 与开发的交接

- 设计同学只提交图标和设计源文件，不修改业务代码、应用配置或发布包。
- 将最终文件放入单独的图标交付目录，并用清楚的文件名标记方向、用途和像素尺寸；保留源文件，不只交一张截图。
- 在开发接入前，由项目负责人对照该文档确认最终方案。接入后分别在 Android 真机/iOS PWA 主屏幕/Windows/macOS 实际启动器中检查显示效果；静态导出成功不等于平台验收完成。
