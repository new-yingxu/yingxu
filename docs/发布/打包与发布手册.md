# 打包与发布手册

> 适用：`workbuddy/dev` 分支。状态：**配置与流程已就位，产物未在本机实测安装**（见文末「未完成」）。

## 1. 版本号

四处必须一致：`backend/tauri-host/tauri.conf.json`、`backend/tauri-host/Cargo.toml`、
`backend/core/Cargo.toml`、`desktop-ui/package.json`。

```bash
scripts/bump-version.sh 0.2.0-draft.2   # 统一改四处
scripts/check-versions.sh               # 复核；CI 与发布门禁都会跑
```

当前基线 `0.2.0-draft.1`。

## 2. 图标

唯一母版：`docs/品牌/影序图标-源图-512.png`（用户定稿：深墨绿底 + 柠檬绿叠层 + 米白「Ai」卡片）。

```bash
python3 scripts/gen-icons.py
```

脚本只做「从母版派生」，不会重绘图形——各端图标与设计稿逐像素同源：

| 产物 | 说明 |
|---|---|
| `backend/tauri-host/icons/icon.png` + `{32,64,128,256,512,1024}.png` | 满幅圆角方形，透明四角 |

换图标只需替换 512 母版后重跑脚本，再重新打包（图标在构建时嵌入 `.app`/`.exe`）。

## 3. 本地打包

```bash
# 1) 前端产物（tauri.conf.json 的 frontendDist 指向它）
cd desktop-ui && pnpm install --frozen-lockfile && pnpm build

# 2) 安装 tauri-cli（与 tauri crate 对齐，CI 用同一条命令锁定）
cargo install tauri-cli --version "^2.12" --locked

# 3) 打包
cd backend/tauri-host
cargo tauri build --bundles dmg          # macOS
cargo tauri build --bundles nsis         # Windows
```

本机注意：系统默认 SDK 与当前链接器不兼容，需指定旧 SDK：

```bash
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX15.4.sdk cargo tauri build --bundles dmg
```

产物位置：`backend/tauri-host/target/release/bundle/{dmg,nsis}/`。

`tauri.conf.json` 的关键项：`bundle.active: true`、`targets: ["dmg","nsis"]`、
`category: Photography`、`macOS.minimumSystemVersion: 11.0`、`macOS.signingIdentity: "-"`（ad-hoc）、
`windows.nsis.installMode: currentUser`。CI 里用 `--bundles` 显式覆盖，避免平台跑不支持的格式。

## 4. 发布流程

```
打 tag  →  gate（fmt/clippy/test/版本一致）  →  macos-14 + windows-latest 构建
        →  finalize：生成 SHA256SUMS 与 latest.json  →  上传到**草稿** Release
        →  人工复核产物与说明  →  手动 Publish
```

```bash
scripts/bump-version.sh 0.2.0-draft.2
git commit -am "chore: bump version"
git tag v0.2.0-draft.2 && git push origin v0.2.0-draft.2
```

- `.github/workflows/release.yml` 由 tag `v*` 触发；也可 `workflow_dispatch` 指定已有 tag。
- 门禁会校验 `tag == v + tauri.conf.json version`，不一致直接失败，阻断发布。
`tauri-cli` 在两个构建任务里用 `cargo install tauri-cli --version "^2.12" --locked` 装并缓存
`~/.cargo/bin/cargo-tauri`，不跟随 `@latest`；`tauriScript: cargo tauri` 让 action 用这把 CLI。
- 产物上传为 **draft + prerelease**，不自动对外——无签名产物必须有人工复核这一关。
- `latest.json` 里 `signature` 恒为空、`updater_enabled: false`：**尚未启用应用内自动更新**，
  不要把清单存在当成更新通道可用。

### 产物与校验

| 资产 | 说明 |
|---|---|
| `*.dmg` | macOS arm64 安装包 |
| `*_x64-setup.exe` | Windows x64 NSIS 安装包 |
| `SHA256SUMS` | 逐文件 SHA-256，官网下载页直接读取展示 |
| `latest.json` | 版本/平台/URL/哈希清单，为将来更新预留；按文件名里的架构精确映射，判不出就告警跳过 |
| `notes.md` | 由 `docs/发布/发布说明模板.md` 渲染并写回 Release 正文（单一来源） |
| `首次打开说明.md` | 放行步骤（也见 `docs/发布/首次打开说明.md`） |

## 6. CI 门禁（`.github/workflows/ci.yml`）

PR 与主干分支触发：`cargo fmt --check`、`cargo clippy -D warnings`、`cargo test`、
`pnpm build`（含 `vue-tsc`）、版本一致性、站点文件与脚本语法。

日常**不跑**打包矩阵（macOS runner 配额有限），只有 tag 才跑两平台。
`tauri-host` 依赖 webkit2gtk，Linux runner 上不编译，由各平台打包任务实际构建。

## 6.5 在 macOS 上交叉编译 Windows（便携版 + NSIS 安装包）

没有 Windows 机器也能出 `.exe` 与**真正的 NSIS 安装包**，两件事分开准备：

### 6.5.1 编译 exe

```bash
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin
cd backend/tauri-host
PATH="/usr/bin:/bin:/usr/sbin:/sbin:$HOME/.cargo/bin:$PATH" \
  cargo tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --bundles app
# 产物：target/x86_64-pc-windows-msvc/release/yingxu-desktop-host.exe
```

### 6.5.2 打 NSIS 安装包（关键：给 Tauri 一把能跑的原生 makensis）

Tauri 的 bundler 在非 Windows 上**不下载** NSIS 工具链，只做两件事：
① 检查缓存里有 `Plugins/x86-unicode/additional/nsis_tauri_utils.dll`；
② 直接调用 PATH 上的 `makensis`（并 `env_remove("NSISDIR")`）。
所以只要把这两件事备齐，macOS 上就能出安装包——不需要 Wine、不需要 Windows。

```bash
# 1) 取原生 makensis（brew 的安装管线在受限环境里会因 sandbox-exec 失败，
#    直接解官方 bottle 更稳。bottle 里编译期写死了 /opt/homebrew 前缀，
#    所以用一层包装脚本把 NSISDIR 指回去）
brew info makensis           # 查当前版本；或直接取 bottle：
# https://formulae.brew.sh/api/formula/makensis.json → bottle.stable.files.arm64_*
# ghcr.io/v2/homebrew/core/makensis/blobs/sha256:<digest>（匿名 token 见 §9 备注）
tar -xzf makensis-bottle.tar.gz -C /tmp/mk

cat > ~/.local/nsis/bin/makensis <<'SH'
#!/bin/sh
export NSISDIR="/tmp/mk/makensis/<版本>/share/nsis"
exec /tmp/mk/makensis/<版本>/bin/makensis "$@"
SH
chmod +x ~/.local/nsis/bin/makensis

# 2) 备好 Tauri 期望的缓存（哈希必须对，否则它会尝试联网重下）
T="$HOME/Library/Caches/tauri/NSIS"
mkdir -p "$T/Plugins/x86-unicode/additional"
# NSIS.exe 与 nsis_tauri_utils.dll 取自 nsis-3.13.zip / nsis-tauri-utils v0.5.3，
# 两个 SHA-1 必须分别等于 tauri-bundler 源码里的常量
# （NSIS.exe 6D45D4E8…、dll 75197FEE…，见 tauri-bundler/src/bundle/windows/nsis/mod.rs）

# 3) 打安装包
PATH="$HOME/.local/nsis/bin:/usr/bin:/bin:/usr/sbin:/sbin:$HOME/.cargo/bin:$PATH" \
  cargo tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --bundles nsis
```

产物：`target/x86_64-pc-windows-msvc/release/bundle/nsis/影序桌面开发版_0.2.0-draft.1_x64-setup.exe`。

**实测（2026-10-26）**：makensis 3.13 + NSIS 缓存，安装器 3,864,384 字节，
PE32 引导器 / GUI 子系统，内嵌 15,281,664 字节的 x64 载荷；`makensis` 只报一条
`warning 5202: -OUTPUTCHARSET is disabled for non Win32 platforms`（无影响）。

CI 上不必这么绕：`windows-latest` 上 bundler 会自己下载并执行 makensis。

### 6.5.3 两个必须知道的约束

1. **必须显式设置 GUI 子系统**。`backend/tauri-host/src/main.rs` 顶部
   `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`；缺了它 release 包会是
   console 子系统，Windows 上多一个黑窗口，关掉黑窗就退出应用。
2. **NSIS 产物是未签名的**。`Warn Signing ... skipping signing the installer`，属预期；
   SmartScreen 会拦，放行步骤见 `docs/发布/首次打开说明.md`。

**顺带修掉的一个编译阻断**：`backend/core/src/fsops.rs` 的 Windows 分支原来用
`MetadataExt::volume_serial_number()/file_index()`（不稳定特性 `windows_by_handle`），
**Windows 目标根本编译不过**（CI 的 windows 任务也会同样失败）。已改为
「创建时间 + 最后写时间 + 文件属性 + 大小」组合作为 identity。

## 7. 已知环境坑：dmg 打包失败

现象：

```
Error failed to bundle project: error running bundle_dmg.sh:
grep: bad regex '/dev/disk5s': brackets ([ ]) not balanced
ERROR: unable to proceed with final disk image creation ...
```

原因：`bundle_dmg.sh` 用 `grep -E` 解析 `hdiutil` 输出。若 PATH 里的 `grep` 不是 BSD/GNU grep
（被工具链注入了 toybox 版等），正则引擎行为不同就会报这个错。**产物本身没问题**，
`.app` 已经正确生成并签名。

绕过：

```bash
# 让子进程用系统 grep
PATH=/usr/bin:/bin:/usr/sbin:/sbin:$PATH cargo tauri build --bundles dmg

# 若仍被环境注入拦截，直接从已签名的 .app 封装（等价产物）
scripts/make-dmg.sh   --app "backend/tauri-host/target/release/bundle/macos/影序桌面开发版.app"   --out "backend/tauri-host/target/release/bundle/dmg/影序桌面开发版_0.2.0-draft.1_aarch64.dmg"   --volname "影序桌面开发版"
```

失败后记得清理挂载：`hdiutil info | grep /Volumes/dmg` → `hdiutil detach /dev/diskN`。
