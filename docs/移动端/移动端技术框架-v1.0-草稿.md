# 影序 YINGXU 移动端技术框架 v1.0（草稿）

> 状态：待产品确认，供移动端负责人拆解实施。本文定义 Android/iOS Expo 客户端及它与 Windows/macOS 桌面客户端的协作接口，不表示代码、第三方资质或设备验收已经完成。
> 执行原则：前端先行；先使用明确的本地 mock/契约样例做页面和流程，产品确认后冻结 API，再接入真实服务。遇到必须申请的 API、应用资质、密钥或账号授权时暂停对应集成，密钥只由负责人放入安全配置，不在聊天或公开仓库传递。

## 1. 总体架构

```text
Expo Android/iOS 客户端 ── HTTPS REST / WebSocket ── FastAPI 业务 API
       │                                          ├── CloudBase：账号/设备/同步数据（能力与计费待核）
       ├── 系统照片/文件授权                      ├── 百度/夸克官方授权 API（逐家接入）
       ├── 本机任务队列与安全存储                  └── Agent 服务：手机本机工具与云端查询工具隔离
       └── EAS Build / 原有下载网页或应用商店分发

Tauri Windows/macOS ── 本地文件/SQLite/任务队列
       └── HTTPS / WebSocket 同步摘要、记录、会话、可选缩略图/路径
```

- 客户端：Expo + React Native + TypeScript；采用 Expo Router，组织路由、登录保护和深链。复核现有 Expo Android 1.0.0 包时，确认其中源码采用 Expo Router、TSX、React Native；此处复用可验证的项目经验，不把旧后端/协议当成新版契约。
- API 中心：移动端不直连 CloudBase 管理接口，不保存服务端密钥。客户端经 HTTPS 访问 FastAPI；CloudBase 为账号/同步数据托管候选，实际鉴权、数据库访问、区域、费用和删除能力实施前核实。
- 桌面端：Tauri 本机执行文件扫描、哈希、复制/上传队列和数据库写入。云端及手机不直接访问桌面文件系统；桌面任务控制只走桌面本地 UI/权限边界。
- 手机本机能力：Expo 模块优先；只有 Expo 公共 API 无法覆盖已确认需求时，增加窄范围 Expo Module/Config Plugin。原生模块不能绕过 OS 权限，也不假设 iOS/Android 拥有相同后台能力。
- 版本与下载：沿用原影序下载网页；EAS 内测/商店发布策略按团队账号和发布成本确认。EAS Update 只分发与原生 runtime 兼容的 JS/资源更新；新增原生模块或改原生配置需要新二进制构建。[Expo EAS Update runtime versions](https://docs.expo.dev/eas-update/runtime-versions/)

## 2. 推荐客户端模块

| 模块 | 职责 | 主要技术选型 |
|---|---|---|
| app-shell | 路由、登录保护、主题、深链、网络状态 | Expo Router、React Native、TypeScript、Safe Area |
| design-system | 颜色语义、字体、间距、按钮、卡片、状态标签 | 主题 token；跟随系统/浅色/深色 |
| auth | 手机短信、邮箱验证码、微信扫码回调与账号绑定 | FastAPI Auth facade；短时 access token + 可撤销 refresh session；系统浏览器/深链回调 |
| account-devices | 账号信息、设备列表、撤销设备 | REST、设备安装 ID；不以 IP 当作设备身份 |
| sync-client | 记录/会话/设置的 outbox、增量序号、重试与冲突处理 | SQLite 本地缓存优先；服务端快照 + WebSocket 增量；幂等事件 |
| desktop-read-model | 桌面状态和历史只读视图 | 明确 schema 的 task snapshot/event DTO；客户端无 desktop-control API |
| mobile-backup | 手机媒体枚举、预检、创建任务、复制/上传、哈希校验、重试 | Expo Media Library/文件系统和系统授权；原生扩展前先做真机可行性验证 |
| cloud-drives | 百度/夸克授权、上传会话、状态与重试 | 服务端 OAuth/token exchange；访问令牌留在服务器或系统安全存储的最小范围，绝不进普通同步日志 |
| thumbnails | 生成/查看压缩预览、关闭同步、清理缓存 | 上传前去除非必要 EXIF；最长边约 512px；独立对象权限与删除策略 |
| agent-client | 流式会话、来源标注、动作预览与确认 | SSE/WebSocket 流式响应；服务端工具白名单；手机和桌面 capability 分离 |
| local-store | 任务队列、缓存、事件游标和用户设置 | SQLite；小型非敏感 UI 偏好可用 AsyncStorage；token/Key 用 iOS Keychain/Android Keystore 包装的 SecureStore |
| notifications | 备份完成/失败、授权失效、桌面状态提醒 | 本地通知优先；推送可选，取决于 APNs/FCM/EAS 凭据和用户许可 |

## 3. 端间接口约定

### 3.1 API 传输

- REST 用于登录会话、设备、任务快照/历史、缩略图元数据、Agent 历史、手机任务创建/状态、设置、导出和删除。
- WebSocket 用于账号设备状态、桌面任务进度、记录和 Agent 流式增量。采用 WSS；重连先读取快照，再带 `after_sequence` 补拉事件；心跳超时显示离线与最后更新时间。
- 桌面设备以出站 TLS 连接云端；不得开放公网端口或让云端主动连入用户电脑。
- 手机专有写接口限定 `device_id` 和 `task_owner=mobile`，服务器拒绝 `desktop` 任务控制 mutation。不要仅靠 UI 隐藏按钮，必须由服务端授权模型拒绝。
- REST/WebSocket 同一事件使用版本化 schema；客户端不能识别的事件安全忽略并记录兼容性告警，不丢弃本地待同步事件。

### 3.2 建议 DTO 字段

```json
{
  "schema_version": 1,
  "event_id": "uuid",
  "sequence": 123,
  "account_id": "opaque-id",
  "device_id": "opaque-id",
  "task_id": "opaque-id",
  "task_owner": "desktop|mobile",
  "media_kind": "photo|video|other",
  "phase": "scan|preflight|copy|upload|verify|done|partial|failed|paused",
  "completed_items": 12,
  "total_items": 20,
  "completed_bytes": 1024,
  "total_bytes": 2048,
  "bytes_per_second": 0,
  "destination_results": [],
  "updated_at": "ISO-8601 UTC"
}
```

- 不把源文件绝对路径、缩略图 URL、完整 Agent 正文塞进通用任务事件。各资源走独立授权接口；隐私开关关闭后服务端停止后续同步并提供已有云端数据删除。
- `event_id` 用于幂等，`sequence` 用于补齐，`schema_version` 用于兼容。任务目的地结果按单目标状态记录，允许本地已完成、百度已完成、夸克失败的部分完成状态。
- Agent 会话同步分为消息、工具调用摘要、用户确认记录和工具结果；附件原片不进入会话同步。工具执行服务端重新校验账号、设备、目标权限和二次确认票据。

## 4. 手机本地备份与后台约束

- 任务状态机：`draft → preflight → awaiting_confirmation → queued → running → verifying → completed | partial | failed | paused | cancelled`。所有写入前需要明确确认；后台恢复从 SQLite 的任务与文件级检查点继续。
- 每个媒体条目记录稳定标识、类型、大小、修改时间、源 URI 权限状态、SHA-256（完成读取后）、每目的地结果和错误码。不得依赖临时 URI 永久可读；重新授权或授权失效时可恢复/报错。
- 对文件冲突执行统一规则：同名同 SHA-256 跳过；同名异内容追加序号；任何覆盖都不作为默认策略。临时文件写完并校验后再原子替换到目标（平台允许时）。
- 网络上传断点续传、分块、服务端校验和幂等键由云盘 API 能力决定；API 不支持时明确显示不可续传，不伪造连续进度。
- Expo `BackgroundTask` 适用于由系统择机执行的可延迟任务：Android WorkManager 最小周期 15 分钟，iOS 由系统决定实际运行时间；不适合作为长时间媒体拷贝/上传的持续运行保证。[Expo BackgroundTask](https://docs.expo.dev/versions/latest/sdk/background-task/)
- 需要用户主动启动且长时间运行的手机备份，必须分别验证 Android 前台服务/通知和 iOS 后台传输会话的正式原生实现、商店政策与真机行为；前后台、锁屏、强制结束、重启、低电量、弱网和权限撤销逐平台验收。未通过前，产品文案限定为“前台运行/系统允许时继续”。

## 5. 数据、隐私与安全

### 5.1 数据归属

| 数据 | 本机 | 影序云端同步 | 规则 |
|---|---|---|---|
| 原始照片/视频 | 手机/桌面原位置或用户选定目的地 | 否 | 可上传至用户授权的百度/夸克个人网盘，不经过影序云端媒体桶 |
| 备份任务/报告 | 有限缓存与队列 | 是 | 可追溯、分目标状态、用户可删；注销时级联删除 |
| Agent 对话与工具摘要 | SQLite 缓存 | 是 | 不含 Key/令牌；用户可删；危险动作保留确认与结果审计 |
| 压缩缩略图 | 缓存 | 用户开启时 | 自动同步，最长边约 512px；隐私提示、独立开关与删除 |
| 桌面完整路径/电脑名称 | 桌面本机 | 用户开启时 | 手机只读查看；个人敏感数据；独立开关与删除 |
| OAuth token / 模型 Key | SecureStore 或服务端密钥库 | 不进入通用同步表、日志或会话 | 最小权限、加密、可撤销；遵守各服务商授权条款 |
| 原始照片 GPS/EXIF | 原片保留 | 默认不额外同步 | 缩略图生成时剥离非必要元数据；逐次云端模型确认 |

### 5.2 授权与威胁边界

- 服务端对账号、设备、资源、动作四层授权；撤销设备后 token 失效或短期内不可刷新。日志避免完整路径、媒体内容、验证码和凭据。
- 访问令牌只保存在 SecureStore/Keychain/Keystore 保护的存储或后端密钥库。Expo SecureStore 是本地 key-value 安全存储，不应被当成大文件/数据库或跨卸载备份方案；恢复与卸载语义需按当前平台文档验证。[Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/)
- 用户可查阅缩略图、路径、会话各自的云端同步开关与删除状态；停用开关后停止新增上传，并提供删除既有同步资料入口。
- Agent 的每个工具声明设备 capability，例如 `query_synced_records`、`manage_mobile_backup`；不得暴露 `control_desktop_backup` 给移动令牌。敏感写操作由服务端要求一次性确认 nonce 并记录审计。
- 百度/夸克 OAuth 应用密钥、微信开放平台密钥、短信和邮件凭据不得放入客户端 bundle、Git 仓库、OTA 更新内容或普通配置；真实授权集成须在获得用户/组织的官方应用权限后进行。

## 6. 视觉规范与主题

参考包移动端源码中的颜色，并与桌面 v0.4 视觉 token 统一。核心 token：

| Token | 色值 | 用途 |
|---|---|---|
| `brand-primary` | `#273D31` | 主按钮、选中态 |
| `brand-deep` | `#253A2F` | 深色品牌/任务面板 |
| `surface-page` | `#F4F2ED` | 浅色页面底色 |
| `surface-card` | `#FFFFFF` | 卡片和弹层 |
| `text-primary` | `#1E2420` | 主文字 |
| `text-secondary` | `#6F706A` | 次级文字 |
| `border-subtle` | `#E9E6E0` | 分隔和边框 |
| `status-success` | `#27804A` | 成功/在线 |
| `accent-progress` | `#DDBA76` | 进度强调 |
| `status-error` | `#A33A32` | 错误/危险操作 |

- 主按钮圆角约 12px、卡片圆角约 18px；间距和字号使用 4/8pt 基准，支持动态字体与安全区域。
- 首轮提供浅色、深色、跟随系统；深色令牌不能只做页面反色，需单独定义背景/卡片/文字/边框/状态色并做对比度检查。
- 状态不能只靠颜色表达，必须配文字或图标；进度信息使用可访问性标签。

## 7. 交付与 CI/CD

- GitHub Actions 执行类型检查、Lint、单元/契约测试和 Expo 配置校验；PR/草稿阶段只生成内部预览，不自动发布到正式渠道。
- EAS Build 按 Android/iOS、development/preview/production 分 profile；构建产物保留版本号、Git commit、runtime version、渠道和校验和。
- 若启用 EAS Update，按 `runtimeVersion` 隔离原生兼容范围；原生模块、权限配置或 app config 改动必须新构建。先 internal preview，再小范围试用，用户确认后才正式发布。[Expo EAS Update](https://docs.expo.dev/eas-update/introduction/) 与 [Deploy updates](https://docs.expo.dev/eas-update/deployment/)
- 推送通知不是任务实时性的唯一来源；实时前台进度依靠 WSS，通知只做完成/失败提醒。通知配置依赖 Android FCM 与 Apple APNs 凭据，密钥由项目管理员在受控环境配置。[Expo Push Notifications](https://docs.expo.dev/push-notifications/push-notifications-setup/)
- 质量门禁：类型/Lint、登录状态、错误状态、脱网快照、增量补齐、幂等、账号隔离、敏感操作确认、任务失败重试、隐私删除和 Android/iOS 真机验收分开报告。模拟器通过不代表真机后台行为通过。

## 8. 分阶段接口/凭据门

1. **UI 原型阶段**：用固定 mock DTO 展示屏幕流程；不得假接真实登录、云盘或桌面控制。
2. **接口冻结阶段**：桌面与手机共同确认任务 DTO、用户/设备模型、事件序号、Agent 会话结构、缩略图/路径授权和删除语义。
3. **账号服务阶段**：确认 CloudBase 区域、数据库与 FastAPI 访问路径、成本、短信/邮箱渠道、微信开放平台资质、账号绑定/注销/删除能力；未确认则停在 mock。
4. **云盘阶段**：逐项申请百度、夸克官方应用/API 权限，核对 OAuth 回调、范围、配额、上传分片/断点续传和删除能力；拿到正式密钥后由负责人配置在服务端安全变量或受控密钥库。
5. **模型阶段**：本地模型不上传原片；云端 BYOK Key 安全保存并显示用量；逐张确认图片后才发给所选模型服务商。
6. **发布阶段**：确认免费自有更新包签名、EAS/商店成本和账号；无平台付费证书的限制按产品既定指引说明，不把 EAS 更新签名与应用商店/操作系统代码签名混为一谈。

## 9. 移动端实现前需要与桌面/API 一起锁定的契约

- `account_id/device_id` 生命周期、设备撤销和同账号多设备冲突规则。
- 桌面任务只读快照与事件字段：速率单位、进度总量、剩余时间置信度、错误码、每目的地状态、离线标识及序号。
- Agent 会话同步字段、流式响应格式、动作摘要/确认记录、手机与桌面工具能力表。
- 缩略图生成/压缩/剥离元数据方式、对象 URL 时效、开关变更和级联删除证明。
- 路径/电脑名隐私开关、账号删除、导出、数据保留及云端备份清理语义。
- 百度和夸克个人授权方式、令牌归属、服务端交换、授权撤回、上传错误码和部分完成行为。
- Expo SDK/原生模块支持矩阵、iOS 长任务可行性、Android 前台服务政策、手机文件目标授权和最低 OS 版本。
