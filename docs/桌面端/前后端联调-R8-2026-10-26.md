# 影序桌面端前后端联调 R8：视频重复分析修复

日期：2026-10-26  
范围：`backend/core/src/video.rs` 以及本轮独立回归；以独立 Tauri 调试应用验证实际原生 IPC。保留既有 V2 前端与 WorkBuddy 的其他后端实现。

## 结论

修复了同一视频重复分析时帧信号从 3 项变成 0 项的问题。原因是分析信号仅在固定名称的帧缩略图首次成功 `write_new` 时加入；第二次分析因缓存文件已存在而将有效信号漏掉。现在每次都基于本次成功解码并完成计算的帧生成信号，缩略图仍只尝试安全新建，不覆盖已有派生图，也不删除任何旧派生图或原片。

## 改动

- 修改 `backend/core/src/video.rs`：将信号统计与缩略图缓存写入结果解耦；继续使用原有 `write_new` 安全写保护。
- 在同文件增加确定性回归：使用带有效内嵌 JPEG 封面的合成 MOV（无需 ffmpeg），连续分析三次，要求每次 `framesAnalyzed == frameSignals.len() == 1`、`decodeStatus == frames_sampled`；同时检查原片内容、修改时间不变，固定名称的派生缩略图未被覆盖，分析帧未上传。
- 没有修改 `media.rs`、`fsops.rs`、`engine.rs`、数据库、网盘、发布脚本或安装包。
