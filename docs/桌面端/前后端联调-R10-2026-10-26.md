# 影序桌面端前后端联调 R10 — Agent 显式恢复本轮（2026-10-26）

## 范围与依据

只修改桌面前端 API adapter、模型授权组件及合成回归检查。云端服务和 `backend/` 保持只读。采用已交接的 v11 HTTP 协议：`POST /v1/agent/turns` 新增可选 `resume:boolean`（默认 false）；显式恢复需要复用原 `sessionId`、`turnId`、`query` 并携带 `useModel:true`、`resume:true`。不传 `thread` 字段。云端 Agent 每次模型响应最多调用 2 个只读工具、整个 turn 最多 4 次只读工具、最多 3 次 provider 请求，并累计不超过 10 条摘要；授权界面只概括最多 3 次模型请求，不把工具执行宣传成文件操作。没有连接 CloudBase 或生产身份。

## 发现与改动

- 原 `MODEL_REQUEST_PENDING`、`MODEL_REQUEST_UNCERTAIN` 等错误虽无自动重试代码，但通用错误文案仍说“保留编号重试”；模型失败提示还会建议主动新建轮次，且“新建模型轮次”按钮在失败后仍能生成新 `turnId`。这会误导用户绕过未知状态。
- `desktop-ui/src/api/cloud.ts` 现把模型首发与恢复分开：普通 `askModel` 不附带 `resume`；`resumeModel` 只在显式调用时发送 `resume:true`，严格使用同一 query/session/turn，并保留服务端 code/status。请求发出前的身份错误标记为本轮未发送；网络请求开始后结果未知不标记安全重发。
- `desktop-ui/src/api/model-consent.ts` 对 pending、uncertain、completed-unretained、网络未知结果锁住新轮次；仅对明确支持的状态暴露恢复能力。恢复也须单独显式确认，配置变化先核对；`CHECKPOINT_NOT_FOUND`、`CHECKPOINT_SYNC_DISABLED`、`RESUME_REQUIRES_SESSION_AND_TURN`、403、410 会关闭恢复入口并保留锁定状态。
- `desktop-ui/src/components/ModelConsent.vue` 在未知状态下禁用“新建模型轮次”，单独展示“查看并恢复本轮”确认对话框，显示原查询及最多 3 次模型请求、可能继续处理并产生供应商用量的说明。只读工具不获文件执行权限。没有自动 resume，也没有通用“重试”按钮。
- 为 R9 本机测试 adapter 增加 `createCloudModelService` wrapper，使 `ModelConsent` 可选使用显式恢复能力；R9 测试页原同轮幂等按钮仍单独控制，不自动走恢复分支。

## 验证

- `desktop-ui/tests/model-recovery-r10.mjs`：8 项通过，日志见 `desktop-ui/evidence/r10-recovery-checks.log`。覆盖协议错误 code/status 保留、pending/uncertain 后禁止新 turn、请求前身份失败不误判发送、网络异常只发一次、普通首发不带 resume、resume 的确切请求体与显式授权、取消不发送、恢复错误后保持锁定。
- `vue-tsc -b` 通过。
- Vite 静态打包通过，产物在 `desktop-ui/evidence/r10-dist/`；未覆盖旧 V2 `dist`。
- 仅使用合成 HTTP fixture；没有发起真实模型请求。未运行云端/SQLite 服务，所以这不是云端 v11 集成验收。

## 待后续核验

- v11 云端显式 resume 的完整服务端行为及 UI 状态组合仍需在非生产合成环境按服务端实际响应验证；本轮只用交接提供的协议与错误码，不改云端代码。
