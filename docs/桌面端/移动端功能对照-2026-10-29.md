## 已确认的桌面缺口

1. **账号与设备跨端闭环未完成。** 桌面登录表单是真实 UI，但 native adapter 的 `auth.login` 当前显式拒绝创建会话；身份 API 的 Rust 模块尚未接入 Tauri 命令。设备列表、设备撤销、跨端设置同步也未连到真实服务。桌面端本地模式仍可独立工作。
2. **两端身份/同步后端不同。** 这份移动包采用 Firebase；桌面框架采用 CloudBase Auth + 影序 API。这不是补一个桌面按钮或 UI 能修复的问题。需要先由项目负责人确定统一身份提供方、账号映射方式、同步 DTO 和迁移策略，再分别由负责端实现。切换桌面到 Firebase 会偏离已批准的桌面技术框架。
3. **旧 Pocket TCP 能力与新版安全边界冲突。** 移动源码可见桌面文件下载以及桌面任务控制；桌面 v0.4 框架明确不向手机开放桌面任务控制/文件路径访问，且已要求新版不沿用旧局域网传输。当前不应由桌面端复刻该协议。

## 实施结论

桌面端本机备份、转移、资料库、任务历史、Agent、归档、健康审计、预设和客户交付均有现有实现；没有发现应把移动端原生权限或移动端专用流程直接移植到桌面端的功能缺项。本轮不改移动端源码，也不引入 Firebase 客户端或旧 Pocket TCP 服务。真正缺失的是“账号/设备/同步”的端到端统一接入；在两端身份及 DTO 契约确认前，桌面端必须保持明确的未连接状态。
