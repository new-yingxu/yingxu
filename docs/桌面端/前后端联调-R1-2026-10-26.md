## 给后端/宿主负责人的具体需求

### V-01：重复视频分析丢失逐帧信号（已复现，未修改后端）

- 对同一生成 MP4，连续两次 `video.analyze{mediaId,extractFrames:true}`。
- 首次 `framesAnalyzed=3`；第二次 `framesAnalyzed=0`，但两次 `decodeStatus=frames_sampled`、`frameSource=ffmpeg_stream_seek`。
- 证据：`desktop-ui/evidence/video-repeat-observation.json`。
- 当前 `backend/core/src/video.rs` 的 analyze_video 中，只有固定名称 `video-<id>-<label>.jpg` 的 write_new 成功才把 sig 推入 signals；重分析时文件已存在，导致有效信号未加入，之后覆盖 quality/framesAnalyzed。
- 建议：信号统计与缩略图写入结果解耦；选择唯一派生名、校验复用或受控原子更新，并正确处理真实写盘失败。需要新增重复分析保留帧数/质量信号的回归场景。
- 前端当前明确显示“有效逐帧信号为 0，结果不完整”，不造出 3 帧，也不显示质量正常。

### H-01：原生 IPC/目录选择器与新前端资源需要实际宿主验收

尝试运行现有调试可执行文件，但桌面工具无法可靠绑定其原生窗口；已停止本轮启动的空任务宿主。两个同 bundle ID 的现有 .app 还使自动定位产生歧义，指定路径读取也超时。**未取得原生窗口/实际 invoke/原生目录对话框的验收证据。**

请宿主/打包线用最新 `desktop-ui/dist` 重建当前宿主，并指定唯一 .app 路径；在 macOS 验证选来源/目标、预检取消/确认、任务更新和报告导出。Windows 仍需要 Windows x64 实际环境验收，不能用本轮浏览器结果替代。

MVP 本地接线没有要求新增后端方法；使用的都是已存在接口。

### C-01：云端接入保持隔离

登录、Agent、本地动作桥和账号/设备同步不属于此轮已验证范围。上一轮只读审查列出的 ack/双游标、账号队列归属、脱敏事件及回执幂等问题仍应由云端和本地传输维护方协调，不能因本地复制成功而宣称已同步。

### D-01：文档与参数差异

`netdisk.completeAuth` 文档写 code 可省略，而现有 ext.rs 的 code:String 没有 default。当前前端不开放未获批网盘授权，因此不依赖此调用；启用前请维护方统一契约。
