# CI、Release 与 Pages 文件范围审查（2026-10-26）

只读审查工作流、`.gitignore`、Tauri bundler 配置及 Git 跟踪路径；未读取任何 `.env` 或 token 值，未提交、推送或发布。

- `backend/.env` 当前存在且被根 `.gitignore` 的 `.env` 规则忽略；Git 跟踪列表中没有此文件。唯一被跟踪的环境样例是 `cloud-service/.env.example`。未查看 `backend/.env` 内容。
- `tauri.conf.json` 的 `bundle` 配置只声明应用图标与 macOS/Windows installer 设置，没有 `resources` 或打包外部凭证文件的配置。核心 CLI 中有 `.env` 加载逻辑，但该文件位于单独的 `backend/core/src/main.rs` CLI 入口；Windows/DMG 当前实物中未做文件系统展开审查。
- CI 没有产物上传步骤。Pages workflow 的上传路径固定为 `site/`；它不会上传项目根目录或 `backend/`。
- Release workflow 由 `tauri-action` 生成 macOS DMG 和 Windows NSIS 资产；finalize 只将 `release-out/*`（生成的 `latest.json`、校验和、首次打开说明和发布说明）上传到 Draft Release。工作流没有上传项目根目录、`.env`、本地数据库或用户照片的步骤。
- Release workflow 将 GitHub 自动令牌传给 `tauri-action` 和 `gh`，权限为 `contents: write`，用途是创建/更新 Draft Release；工作流没有打印令牌的命令。当前尚无该 workflow 的运行记录，因此本轮只核了配置，没有 GitHub Actions 日志或发布资产可供运行期检查。
- Git 跟踪清单中没有 RAW/JPEG/视频素材；图像文件仅是应用/网站图标。无用户原片在当前跟踪清单中。

## 限制

这是基于工作流配置与 Git 跟踪路径的静态范围审查，不证明未来修改后的 workflow 仍保持相同范围，也不对 GitHub 托管端秘密库取值或 Actions 执行环境进行读取。
