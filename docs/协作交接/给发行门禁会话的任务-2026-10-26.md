### 任务 A：发行门禁补全

目标：把"发一个包之前必须过的检查"从纸面脚本变成有运行证据的门禁。只新增/修改 `scripts/` 内文件与 `scripts/evidence/` 证据目录。

A1. **`scripts/scan-secrets.py`（新建）**
    - 对齐云端 `verify_function_context.py` 的能力，但对象是桌面产物（`.dmg` / `.exe` / `.zip`）。
    - 扫描目标文件字节流中的：`sk-` 开头串、`AKIA` 开头串、`-----BEGIN` 私钥块、`SECRET`/`PASSWORD`/`TOKEN` 高熵赋值、CloudBase/百度/夸克凭据模式。
    - 输出 JSON 报告（命中的偏移量前后 32 字节的上下文，**不输出完整凭据**），退出码：0 干净 / 1 发现疑似 / 2 参数错误。
    - 自测：构造一个含假密钥的小文件跑通，证据存 `scripts/evidence/scan-secrets-selftest-<日期>.log`。

A2. **`scripts/check-release-consistency.py`（新建）**
    - 输入：一个资产目录（含安装包 + `SHA256SUMS.txt`）。
    - 校验：① SHA256SUMS 与实际文件逐一相符；② 资产文件名内嵌版本 == `tauri.conf.json` version == 两个 Cargo.toml == `desktop-ui/package.json`（复用 `check-versions.sh` 的四处逻辑，保持单一实现，脚本内调用它而非复制）；③ `gen-latest-json.py` 能对该目录生成 `latest.json` 且平台字段与实际文件对应。
    - 输出人类可读报告 + 退出码语义同上。
    - 对 `docs/协作交接/windows-安装测试/安装包/` 实跑一次并存证据（该目录版本是 0.2.0-draft.1，预期**通过**）。

A3. **存量脚本实测补证**
    - `check-versions.sh`、`gen-latest-json.py`、`render-release-notes.py` 各真实运行一次（构造最小输入，不改仓库既有版本号），证据存 `scripts/evidence/`。
