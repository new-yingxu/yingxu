3. **Windows 运行层：未验。** 没有可用的隔离 Windows x64 VM，也没有现存 GitHub Windows UI 验收运行。本轮未运行安装器或 EXE，不能说修复回归通过。环境证据见[Windows 环境检查](独立验收证据-2026-10-26/Windows环境检查-2026-10-26.md)。
4. **发行外泄路径：配置审查未发现当前工作流会上传 `.env` 或用户照片。** Pages 只上传 `site/`，Release 只上传应用安装包和 `release-out` 元数据；本地 `backend/.env` 未被 Git 跟踪且受忽略规则保护。配置审查不能代替未来 workflow 修改后的复查，详见[发行路径审查](独立验收证据-2026-10-26/发行文件范围审查-2026-10-26.md)。

## CI/CD、Pages、Release 风险边界

- `.github/workflows/ci.yml` 使用 Ubuntu，不上传工作区文件。
- `.github/workflows/pages.yml` 的 `upload-pages-artifact` 路径固定为 `site`。
- `.github/workflows/release.yml` 构建 macOS DMG 和 Windows NSIS；finalize 只上传生成的 `release-out/*` 元数据及说明到 Draft Release。`tauri-action` 使用 `GITHUB_TOKEN` 上传 Release 资产，workflow 权限为 `contents: write`；未发现打印令牌或上传项目根目录的命令。
- 根 `.gitignore` 忽略 `.env` 与 `.env.*`；`backend/.env` 存在但不在 Git 跟踪列表中。本轮未读取其内容。跟踪文件中未发现 RAW/JPEG/视频用户素材；被跟踪图像为应用和站点图标。
- GitHub 远端仓库为公开仓库 `new-yingxu/yingxu`。本轮 Actions 运行列表为空，未观察到远端执行或实际发布资产。
- 这只能证明当前配置的已知文件范围；第三方 Action 代码本身未做供应链审计。Release job 向 `tauri-action` 提供有写权限的自动令牌，应继续保持仅在可信 tag/人工触发时运行并使用 draft；未来改工作流时需重做范围审查。
