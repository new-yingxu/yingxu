> **分工已定（2026-10-26）**：申请由**你本人**来走（要实名/登录你的账号），本文就是照着做的操作单；
> 拿到凭证后我接手改代码联调。安卓/苹果端与此无关（另有同学负责）。

> 目标：拿到 `Appid / AppKey / SecretKey / SignKey` 与可用的 `redirect_uri`，先在**自己的账号**上跑通
> 一次真实目录上传，再考虑公开发布。
> 依据：百度网盘开放平台官方文档（2026-08 控制台改版后的口径）。

## 关键判断：先申请「个人使用」，不要一上来走公开发布审核

官方文档明确：**「应用用途」选「个人使用」创建后直接可用，免上线审核**；公开发布才需要
提交应用名称、描述、功能类别、测试信息、API 必要性说明、演示视频、邮箱、付费电话、隐私政策 URL 等，
并由审核团队**实机走查安装 → OAuth → 核心功能 → 卸载**。

所以路线是两段：

| 阶段 | 用途 | 审核 | 拿到什么 |
|---|---|---|---|
| ① 个人使用 | 自己账号联调，验证上传/续传/校验 | **免审核，创建即用** | Appid / AK / SK / SignKey |
| ② 公开发布 | 给别的用户用 | 需提交材料 + 实机走查 | 上线资格、可申请的 API 白名单 |

**先做①**。跑通后再决定要不要②——②要演示视频和隐私政策上线地址，成本高，且我们证书还没到。

## ① 个人使用：四步

### Step 1 注册与认证

1. 打开 <https://pan.baidu.com/union>（网盘开放平台）→ 右上角用**百度账号**登录。
2. 首页「快速接入」→ 同意《百度网盘开放平台开发者服务协议》。
3. 按提示完成**实名认证**（个人：身份证 + 人脸；企业：营业执照）。
   - 个人主体也能创建「个人使用」应用；**公开发布**通常要企业主体。

### Step 2 创建应用（照抄下面的字段）

| 字段 | 填写 |
|---|---|
| 应用用途 | **个人使用** |
| 应用名称 | 影序 YINGXU 桌面端 |
| 应用分类 | 工具效率 |
| 应用描述 | 本地影像备份工具：先在本机完整备份并逐文件 SHA-256 校验，再把用户选中的文件上传到用户自己的网盘账号作为异地副本。 |
| 回调地址 | 见 Step 3（先填占位也要填一个能对上的） |

### Step 3 回调地址：desktop 的真实难点

百度要求 `redirect_uri` 与申请值**严格一致**，且公开应用通常要求 HTTPS + 备案域名。
桌面端习惯的 `http://127.0.0.1:<随机端口>/callback` **很可能不被接受**。三个选项：

| 方案 | 可用性 | 代价 |
|---|---|---|
| A. `redirect_uri=oob`（out-of-band） | 部分应用可用；授权后页面直接显示 code，用户粘贴回应用 | 需要 UI 加一个"粘贴授权码"输入框（改动小） |
| B. 固定 loopback `http://127.0.0.1:8765/callback` | 取决于平台是否放行 http；需把端口写死 | 代码里把 `bind(..., 0)` 改成 `8765` |
| C. 自有 HTTPS 中转页 | 最稳，符合审核口径 | 需要一个已备案域名 + 一个转发页（把 code 显示给用户复制） |

**建议顺序：先试 B（改一行、体验最好）→ 不行退 A（加一个输入框）→ 长期上 C（配合官网上线）。**
选哪个告诉我，我改 `netdisk_begin_auth` 与 UI 的对接方式。

### Step 4 拿凭证并本地联调

控制台「我的应用」列表页看不到凭证——要点该行的 **「编辑」进入应用详情页**：

- `Appid / AppKey / SecretKey / SignKey` 就在详情页（SecretKey / SignKey 默认打码，点「显示」）；
- 同一页的 **「安全设置」→「授权回调地址」** 配 `redirect_uri`，支持多个（逗号分隔）；
- 回调必须与申请值**一字不差**（协议/端口/路径），否则授权时报 `redirect_uri_mismatch`；
- 个人开发者最多可创建 **2 个应用**，注意省名额。

官方口径见「接入流程」文档：pan.baidu.com/union/doc（基础网盘服务 → 平台简介 → 接入流程）。

拿到后**不要贴到聊天里**，按下面放：

```bash
# 只放本机，不进仓库（.gitignore 已忽略 .env）
cat > backend/.env <<'EOF'
YINGXU_BAIDU_APPID=...
YINGXU_BAIDU_APPKEY=...
YINGXU_BAIDU_SECRETKEY=...
YINGXU_BAIDU_SIGNKEY=...
EOF
```

我这边接手做三件事（约半天）：

1. `providers()` 里百度改 `approval: "approved"` 并填真实 `auth_endpoint`/`token_endpoint`；
2. 引入 HTTPS 传输层（`reqwest` + rustls，包体积约 +1.5 MB），`http_post` 换成能走 TLS 的实现；
3. 按其文档对齐分片协议（precreate → part → merge，字段名与分片上限），用真实账号跑一次
   「目录上传 + 断网中断 + 续传 + 远端 SHA-256 一致 + 解绑」。

验收口径：**真实账号里能看到文件、哈希与本地一致、断网续传不重传已完成分片、解绑后令牌失效**。

## ② 公开发布（等①跑通再启动）

需要准备的材料（官方审核表）：

| 字段 | 我们要准备什么 | 现状 |
|---|---|---|
| 应用名称 / 描述 | 已有文案 | ✅ |
| 功能类别 | 工具效率（单选） | ✅ |
| 测试信息 | 安装包 + 测试账号 + 操作指引 | 安装包待 CI；测试账号可提供 |
| 申请 API 列表 + 必要性说明 | 只申请 `netdisk.upload` 类 + 用户信息，逐条写清"为什么需要" | 待写 |
| 演示视频 | OAuth 登录 → 选目录 → 上传 → 校验 → 解绑（3 分钟内） | 待录 |
| 隐私政策 URL | 官网站点 `privacy.html` | 待 Pages 上线 |
| 联系邮箱 / 付费电话 | 你的联系方式 | 待补 |

审核会**实机走查安装 → OAuth → 核心功能 → 卸载**，所以安装包与卸载路径必须先能过（NSIS 安装包已于 2026-10-26 产出，见 `windows-安装测试-2026-10-25.zip`）。

## ③ 夸克：**硬阻塞——没有公开 API**（2026-10-26 核实）

> 修正此前的判断（"准入更窄"是推测）。实测核实：
>
> - `open.quark.cn`（夸克开发者平台）只有浏览器插件与 AI 能力，**没有网盘文件 API**、
>   没有 AppKey 申请入口、没有 OAuth 文档；
> - `developer.quark.cn` 同样不含网盘能力；
> - 社区流传的"夸克 API"全部是对内部协议的逆向（违反《夸克用户协议》4.3 条），
>   随签名算法更新随时失效，**不能作为产品能力**。
> - CSDN 问答（2026-04）引用官方现状与此一致。

**结论：夸克接入无操作可做，代码侧接口骨架保留（provider 标记 `no_public_api`），等官方开放。**

**最终决策（2026-10-26）：网盘只做百度**，第二条网盘通道暂不引入。
