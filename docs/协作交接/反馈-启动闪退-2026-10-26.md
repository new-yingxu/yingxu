## 6. 关键证据

### 6.1 第一个实例确实在运行（崩溃前）

```
PID            : 21680
启动时间       : 2026-10-26 00:26:33
Responding     : True
MainWindowHandle: 590854      ← 窗口存在
窗口标题        : 暂缺        ← 但不可见（托盘驻留形态）
线程数          : 38
CPU 时间        : 0:00:08
子进程          : msedgewebview2.exe (PID 15368)  ← WebView2 界面已加载
```

### 6.2 数据库锁是被真实持有的

```
$ od -c "%APPDATA%\app.yingxu.desktop.next\worker.lockfile"
od: .../worker.lockfile: read error: Device or resource busy
```

说明 `worker.lockfile`（0 字节）上挂着**操作系统级排他锁**，由运行中的进程持有。

### 6.3 结束进程后，锁释放、启动恢复

| 时间 | 操作 | 结果 |
|---|---|---|
| 00:26:33 | 双击启动 | 成功（PID 21680），窗口隐藏到托盘 |
| 00:35:41 | 再次双击 | panic，退出码 101 |
| 00:36:46 | `taskkill /PID 21680 /T /F` 后重新启动 | **成功**（PID 20380），窗口标题「影序 YINGXU · 开发版」 |
| 00:37:03 | 在 PID 20380 运行时再次双击 | **稳定复现** panic，退出码 101 |
| 00:40:00 | 生成本报告时 | PID 20380 仍在正常运行 |

**结论：只要有一个实例存活，后续每一次双击都必然 panic。** 100% 复现。

---

## 7. 根因分析

1. **缺少单实例处理。** 第二次启动没有检测"已有实例"，也没有向已有实例发送"显示窗口"的信号（Tauri 常规做法是 `tauri-plugin-single-instance`，或命名互斥体 + 进程间消息）。
2. **把"已在运行"当成了致命错误。** 数据库层的"单 worker"约束在 setup hook 里变成 `Err`，Tauri 随即 panic 退出，而不是走"唤回窗口"的正常分支。
3. **错误对用户不可见。** 这是 GUI 子系统程序，panic 只写到 stdout（无控制台），用户看不到任何提示，只能看到窗口闪一下。
4. **数据目录里的 `worker.lockfile` 本身不会造成残留问题。** 它是 OS 级锁，进程退出即释放（已实测：kill 后可正常读取）；0 字节的残留文件无害。**不需要**手动删除它。

## 8. 临时规避（测试期间可用）

- **不要重复双击 exe。** 程序已在运行时，用托盘的图标唤回窗口（图标可能在任务栏右下角的 `^` 展开区里）。
- 需要重新启动时，先结束进程再双击：

  ```bat
  taskkill /IM "影序桌面开发版_0.2.0-draft.1_x64-portable.exe" /T /F
  ```

  或在任务管理器里结束「影序桌面开发版」。

## 9. 建议修复

| 优先级 | 建议 |
|---|---|
| P0 | 接入 `tauri-plugin-single-instance`：第二次启动时 `show()` + `set_focus()` 已有主窗口，然后第二个进程静默退出 |

## 11. 其他观察（非缺陷）

- 便携版没有 `Zone.Identifier` 标记，说明不是从网络直接下载后运行；SmartScreen 未拦截。
- 交叉编译产物在 panic 信息中带有出包机路径，不影响运行。
- 崩溃没有产生 Windows 错误报告（WER）事件，因为 Rust panic 是正常退出（101），不是访问违例——所以**事件查看器里查不到**，排查时要靠控制台输出。

## 12. 附带建议：如何自行取证

用 PowerShell 或 cmd 在 exe 目录下直接运行，就能看到 panic 原文（GUI 程序在资源管理器里双击看不到）：

```bat
cd /d "程序目录"
"影序桌面开发版_0.2.0-draft.1_x64-portable.exe"
echo 退出码=%ERRORLEVEL%
```

需要更详细的栈时：

```bat
set RUST_BACKTRACE=full
"影序桌面开发版_0.2.0-draft.1_x64-portable.exe"
```

## 修复记录（2026-10-26，出包方回填）

按 §9 的建议逐条处理：

| 建议 | 处理 |
|---|---|
| P0 单实例处理 | ✅ 接入 `tauri-plugin-single-instance`（注册为第一个插件）：第二实例启动时，第一实例收到回调并 `show + unminimize + set_focus` 主窗口，第二实例静默退出（退出码 0）。Windows/macOS 同时生效 |

| P2 崩溃日志落盘 | ✅ 2026-10-26：全局 panic hook，把消息/位置/线程名/回溯写入 `%APPDATA%\app.yingxu.desktop.next\logs\crash-<UTC时间>.log`（macOS 在 `~/Library/Application Support/...`），自动保留最近 20 份 |
