## 结论与已知缺口（2026-10-26 更新）

**能做到的**：8 个真实样本里 7 个能提内嵌预览，**7 个能读到拍摄字段**；原片 8/8 分析前后 SHA-256 不变。
预览来源三条路径都生效：TIFF IFD（CR2/NEF/ARW/ORF）、RAF 头偏移（富士）、JPEG 流扫描（CR3/RW2）。

**本轮修掉的两个识别缺陷**：

1. **CR3 的 EXIF**（原缺口）：沿 BMFF 找 `uuid` 盒，CMT2 盒内偏移 264 处是一段完整 TIFF，
   复用 TIFF-IFD 读取器即可拿到 Make/Model/时间。实测 `Canon EOS R6` + `2021-05-12 12:21:21`。
   该样本**没有 ExifIFD**，所以 ISO/光圈/快门不可得；时间是 IFD0 的 0x0132，故
   `timestampSource=tiff_datetime`，**不冒充快门时间**（另给 `ifdDateTime` 字段）。
   修复过程中发现扫描前未 `seek(0)` 导致起点错位的 bug，已加回归测试
   `cr3_exif_comes_from_cmt2_uuid_box`（含"先把文件指针挪开"的断言）。
2. **坏文件名不再拖垮整批扫描**：真实样本原名带 `1:1`/`16:9`，旧实现会整目录返回 `UNSAFE_PATH`。
   现在改为跳过并逐条报告。端到端实测（一个正常文件 + 一个 `ratio 1:1.cr2` + 一个符号链接）：

   ```
   library.index → files: 1, skippedCount: 2
     skip: link.cr2      -> symlink          | 不跟随符号链接
     skip: ratio 1:1.cr2 -> unportable_name  | 包含冒号（在 Windows 上无法创建同名文件）
   backup.scanReport → scanned: 1, skippedTotal: 2, truncated: false
   ```

**仍做不到的（如实记录）**：

1. **Blackmagic Cinema DNG**：文件里没有内嵌预览（Cinema DNG 逐帧 DNG，不带 JPEG 预览），
