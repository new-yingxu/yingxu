## 2. 申请材料（可直接复制）

### 2.1 应用基本信息

| 字段 | 建议填写 |
|---|---|
| 应用名称 | 影序 YINGXU 桌面端 |
| 应用类型 | 桌面应用（macOS / Windows） |
| 一句话简介 | 本地影像备份与整理工具，用户自选网盘作为额外副本目标 |
| 详细说明 | 用户在桌面端选择本地影像目录，影序按用户设置复制到本地磁盘/个人网盘。上传由本机直连目标网盘完成，影序服务端不中转、不存储用户原片。 |
| 回调地址 | `http://127.0.0.1:<随机端口>/callback`（PKCE + loopback，端口运行时分配） |
| 需要的 scope | 百度：`basic`、`netdisk`；夸克：`file:write`（最小化原则，不要申请读全盘） |
| 是否商用 | 视你的分发方式填写；不收费也要如实说"免费分发" |

**回调地址写法要点**：桌面端无法固定端口，必须在申请时说明"loopback + PKCE，端口运行时分配"，
并提供上方这个通配说明；若平台只接受固定地址，退路是注册 `http://127.0.0.1:8765/callback`
并在代码里固定该端口（`netdisk_begin_auth` 里把 `TcpListener::bind(("127.0.0.1", 0))` 改成固定端口）。

### 2.2 场景说明（审核最看重这段）

> 用户是摄影师/摄影爱好者，一次拍摄产生几十 GB 素材。影序的做法是：本地磁盘先做完整备份并逐文件
> SHA-256 校验，通过后才把**用户自己选择的**文件排队上传到**用户自己已授权的**网盘账号，作为异地副本。
>
> - 影序不提供云端存储服务，不代持用户文件；
> - 上传目标、并发数、限速均由用户设置；
> - 失败只重试失败分片，不会把失败写成成功；
> - 解绑时删除本机令牌，保留历史结果记录。
>
> 我们不读取用户网盘里的既有文件，只写入用户明确选择的目录。

### 2.3 隐私与合规

- 隐私政策：官网站点 `privacy.html`（部署后填公网地址）
- 数据流说明：原片 → 目标网盘（直连），影序服务端不参与
- 令牌存储：系统凭据库（Keychain / Credential Manager / Secret Service），不入数据库与日志

## 3. 审核常见拒绝原因（提前避开）

1. **场景描述空泛**（"提供云存储服务"）→ 会被当成网盘竞品；强调"个人备份工具、用户自己的账号"。
2. **scope 过大**（申请全盘读写）→ 只申请写入 + 必要元信息。
3. **回调地址与代码不一致** → 申请里的地址必须与 `netdisk_begin_auth` 生成的一致。
4. **没有可演示的产品** → 准备好截图/录屏：备份完成页、上传队列、失败重试。
5. **无隐私政策或地址打不开** → 先把站点部署上线（Pages），再提交。

## 4. 获批后要改的代码（现在已留好位置）

| 改动点 | 位置 | 说明 |
|---|---|---|
| 审批状态 | `backend/core/src/netdisk.rs` → `providers()` 里的 `approval` | `"pending"` → `"approved"`，同时删掉 `require_runnable` 的例外 |
| 真实授权地址 | 同上 `auth_endpoint` / `token_endpoint` | 换成平台文档给出的真实地址 |
| 传输层 | `http_post` | 现在只支持明文 http（给 mock 用）。真实厂商必须 HTTPS：引入 `reqwest`（rustls，无 OpenSSL）或 `ureq`+rustls，包体积约 +1.5 MB |
| 分片协议 | `netdisk_run` | 百度是 precreate + part + merge 三段，字段名与分片大小上限需按其文档调整；夸克用 md5 校验需补一列 |
| 限流与并发 | `UploadOptions` | 已支持 `maxConcurrency` / `maxMbps`，按平台配额设默认值即可 |
| 解绑 | `netdisk_unbind` | 补一次"撤销授权"的远端调用（现在只删本地令牌） |
| 结果记录 | `netdisk_tasks` | 可加远端文件 id / 分享链接（如平台返回） |

**HTTPS 传输层引入时机**：与资质获批一起做，避免在没资质时引入依赖与构建体积。
现在不引入是刻意的，不是遗漏。
